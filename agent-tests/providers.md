# 模型提供商管理 — agent-browser 测试场景

> 由 Claude Code 调用 `agent-browser` skill 执行，或人工逐项验证。

---

## 提供商配置

**首次配置（百炼）**
1. 进入 `#/providers`，显示百炼提供商卡片，状态标签为「未配置」
2. 点击「编辑配置」进入编辑态
3. 点击「Coding Plan」快捷按钮，自动填充 Coding Plan 格式 Base URL
4. 填写 API Key（`sk-sp-` 前缀格式），验证提示应显示格式正确
5. 点击「保存」，卡片状态标签变为「Coding Plan」

**按量计费配置**
1. 点击「编辑配置」进入编辑态
2. 点击「按量计费」快捷按钮，自动填充按量计费 Base URL
3. 填写 API Key（`sk-` 前缀格式），验证提示显示格式正确
4. 保存后状态标签变为「已配置」

**重新配置**
1. 已配置状态下点击「编辑配置」
2. Base URL 和 API Key 字段变为可编辑状态
3. API Key 字段显示掩码（前 8 字符 + `***`）
4. 修改保存后配置更新，测试结果清除

## 格式验证

**API Key 前缀校验**
- Key 前缀为 `sk-sp-` 且 URL 为 Coding Plan 格式：验证通过（无警告）
- Key 前缀为 `sk-` 且 URL 为按量计费格式：验证通过（无警告）
- Key 前缀为 `sk-sp-` 但 URL 为按量计费格式：显示黄色「格式不匹配」警告，保存按钮禁用
- Key 前缀为 `sk-` 但 URL 为 Coding Plan 格式：显示黄色警告，保存按钮禁用
- Key 为空时：显示必填错误，保存按钮禁用
- Base URL 不是 http/https 开头时：显示格式错误，保存按钮禁用

**URL 变更提示**
- 修改 Base URL 时，卡片显示紫色提示，说明将测试的接口格式（OpenAI / Anthropic）

## 测试连接

**成功场景**
1. 已配置 API Key 和 Base URL 的情况下，点击「测试连接」
2. 按钮显示「测试中…」禁用状态
3. 成功：卡片内显示绿色「✓ 连接成功」徽章 + 延迟信息

**失败场景**
1. 使用无效 API Key 点击「测试连接」
2. 卡片内显示红色「✗ 连接失败」徽章 + 错误详情文本

**未配置时禁用**
1. Base URL 或 API Key 为空时，「测试连接」按钮禁用，鼠标悬停显示提示

## 模型列表

**查看模型**
1. 提供商已配置后，卡片下方显示模型列表表格
2. 列表显示：模型名、上下文窗口（格式：`128K`、`1M`）、输入类型、能力标签
3. 具有 Vision 能力的模型显示「Vision」标签
4. 支持 Streaming 的模型显示「Streaming」标签

**数值格式化**
- 上下文窗口超过 1,000,000 tokens 时显示为「XM」
- 超过 1,000 tokens 时显示为「XK」
- 模型列表为空时显示空状态，不显示「0 models」

## 多提供商类型

> 系统支持三种 API 协议：`openai-completions`（OpenAI 兼容）、`anthropic-messages`、`gemini`。
> 以下场景验证各协议类型的创建、连接测试和删除流程。

**创建 OpenAI 兼容提供商（如火山方舟）**
1. 点击「添加提供商」按钮
2. 在 Base URL 输入框填入火山方舟地址（`https://ark.cn-beijing.volces.com/api/v3`）
3. 系统自动识别（`suggest_provider`）并建议名称 `volcengine`、协议 `openai-completions`，同时预填模型列表（Doubao Seed 系列）
4. 填写 API Key，点击「保存」，卡片出现在提供商列表，协议标签显示「OpenAI 兼容」
5. 点击「测试连接」：调用 `/models` 端点，成功显示绿色徽章 + 延迟

**创建 Anthropic 协议提供商（如 MiniMax）**
1. 点击「添加提供商」按钮
2. 填入 MiniMax Base URL（`https://api.minimax.io`）
3. 系统自动识别协议为 `anthropic-messages`，建议名称 `minimax`，预填模型列表
4. 填写 API Key，保存，协议标签显示「Anthropic 兼容」
5. 点击「测试连接」：调用 `/v1/messages` 端点（或 fallback 探测），成功返回绿色徽章

**创建 Gemini 协议提供商**
1. 点击「添加提供商」按钮
2. 填入 Gemini Base URL（如 `https://generativelanguage.googleapis.com/v1beta`）
3. 系统识别协议为 `gemini`，建议名称
4. 填写 API Key，保存，协议标签显示「Gemini」
5. 点击「测试连接」：调用 `/models?key=...` 端点，成功返回绿色徽章

**自动识别不到时手动选择协议**
1. 填入一个注册表中不存在的自定义 Base URL
2. `suggest_provider` 返回 null，协议下拉显示为默认（`openai-completions`）
3. 手动从下拉选择协议类型，填写名称和 Key 后正常保存

**提供商名称重复**
1. 尝试创建与已有提供商同名的新提供商（`name` 字段相同）
2. 保存时提示「Provider name "xxx" already exists」，Modal 不关闭

**删除提供商**
1. 选中一个已配置的提供商，点击「删除」
2. 出现确认对话框（若有）；确认后卡片从列表消失
3. 进入 `#/agents`，原先选用该提供商模型的 Agent，模型字段显示为空或「已移除」，不崩溃

## 模型批量同步（set_models）

> `set_models` 接口对指定提供商执行覆盖写（upsert + 删除未列出的模型），以下场景验证 UI 触发该接口的全流程。

**通过「更新模型列表」按钮同步**
1. 选中一个已配置的提供商卡片，点击「更新模型列表」（或「同步模型」）按钮
2. 按钮显示「同步中…」禁用状态
3. 成功后模型列表刷新，显示最新模型数量（如「8 个模型」）
4. 若服务端预置了该提供商的模型（来自 `KNOWN_PROVIDERS`），列表与注册表一致

**手动编辑模型列表**
1. 进入提供商「模型管理」编辑态
2. 可手动添加模型：填写 `model_id`、`display_name`、上下文窗口、输入类型、能力（Vision / Streaming）
3. 提交后列表追加该模型，不影响已有模型
4. 取消勾选某个模型（或点击删除），该模型从列表消失
5. 点击「保存」，调用 `set_models`，本次保存的模型为最终列表（未列出的旧模型被删除）

**覆盖写验证**
1. 提供商原有 5 个模型，手动编辑只保留 2 个并保存
2. 调用 `set_models` 后，数据库中该提供商的模型数量变为 2
3. 在 Agent 模型下拉中，该提供商只显示剩余的 2 个模型

**模型列表为空时**
1. 提供商已配置但模型列表为空时，模型区域显示「暂无模型，请同步或手动添加」空状态
2. 不显示表格头部，不显示「0 个模型」等歧义文字

**数值格式化（`context_window`）**
- `128000` → 显示「128K」
- `1000000` → 显示「1M」
- `200000` → 显示「200K」
- `200` → 显示「200」（不加 K 后缀）

## 边界情况

- 编辑配置时先清除之前的测试结果（成功/失败徽章消失）
- 保存成功后自动退出编辑态
- 保存失败时保持编辑态并显示错误 toast
- 模型列表加载中显示加载占位符，不展示旧数据
- 同时存在多个提供商时，Agent 模型下拉按提供商分组展示，各组标题为提供商名称
- 提供商被禁用（`is_enabled = 0`）时，Agent 模型下拉中该提供商的模型灰显或不显示
