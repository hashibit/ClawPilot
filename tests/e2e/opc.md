# OPC 管理 — agent-browser 测试场景

> 由 Claude Code 调用 `agent-browser` skill 执行，或人工逐项验证。

---

## CRUD

**创建 OPC**
1. 进入 `#/opc`，点击列表底部「创建团队」按钮
2. 弹出创建 Modal，包含「内部名称」「显示名称」「描述」三个字段和 5 个颜色预设
3. 不填写任何字段直接点提交：两个必填字段出现红色错误提示，Modal 不关闭
4. 填写内部名称和显示名称，选择头像颜色，点击提交
5. Modal 关闭，列表出现新建的 OPC 卡片，卡片显示 Avatar 首字母（displayName 前 2 字符）

**取消创建**
1. 点击「创建团队」打开 Modal
2. 填写部分内容后点取消或点 Modal 外区域
3. Modal 关闭，列表无新增条目

**选中 OPC 查看详情**
1. 点击某个 OPC 卡片，右侧面板加载该 OPC 的基本信息
2. 面板顶部显示 OPC 名称和状态（运行中 / 已停止）
3. 统计数据区显示 agent_count、channel_count、message_count_today

**删除 OPC**
1. 选中一个 OPC，点击「删除」
2. 出现确认对话框
3. 取消后 OPC 仍存在；确认后列表中该 OPC 消失
4. 若删除的是当前选中项，自动切换到其他 OPC

## 快照管理

**创建快照**
1. 选中某个 OPC，在快照区点击「创建快照」
2. 弹出输入框，可填写自定义标签；留空则自动生成时间戳标签
3. 确认后快照列表出现新记录
4. 自动快照显示黄色标签 + ✓ 图标，手动快照显示紫色标签

**恢复快照**
1. 点击某条快照的「恢复」按钮
2. 出现确认对话框，说明将覆盖当前所有配置
3. 确认后 OPC 配置恢复到快照时的状态，面板内容同步更新

**删除快照**
1. 点击某条快照的「删除」按钮
2. 无确认，直接从列表消失

## 导出 OPC

1. 选中某个 OPC，点击「导出」按钮
2. 浏览器触发下载，文件名为 `{opc.name}.json`
3. 打开文件，验证内容包含完整 OPC 配置（name、displayName、agents 等字段）

## 导入 OPC

> 导入使用 `import_opc` 接口，以 JSON 字符串覆盖写入，支持完整还原（`INSERT OR REPLACE`）。

**基础导入流程**
1. 点击「导入」按钮（或上传入口），弹出文件选择对话框
2. 选择此前由「导出」生成的 `{opc.name}.json` 文件
3. 确认后系统解析 JSON，调用 `import_opc` 接口
4. 成功提示「导入成功」，OPC 列表中出现（或刷新）该 OPC 卡片

**验证导入完整性（导出 → 导入 → 核查）**

> 建议先用一个包含完整数据的 OPC 执行导出，再导入到空白环境或同一环境，逐项核查：

1. 进入 `#/agents`，选中导入后的 OPC：
   - Agent 列表数量与导出前一致
   - 每个 Agent 的显示名称、岗位名称、颜色、`is_default` 状态均正确
2. 逐一进入每个 Agent 查看人格文档（SOUL / IDENTITY 等）：
   - 7 个 Tab 内容与导出前一致，无截断
3. 进入 `#/bindings`，选中导入后的 OPC：
   - 渠道配置（飞书 / 钉钉 / Slack）显示正确，脱敏展示密钥
   - 群组绑定列表数量与导出前一致，关联 Agent 名称正确
4. 返回 `#/opc`，核查统计数据（agent_count、channel_count）与导出前一致

**覆盖已有 OPC**
1. 对一个已存在的 OPC（相同 `id`）执行导入
2. 数据被覆盖写入（`INSERT OR REPLACE`），不产生重复条目
3. 导入后进入该 OPC，数据反映导入文件的内容（而非旧数据）

**导入格式错误**
1. 上传一个非 JSON 文件（如 `.txt` 纯文本）
2. 解析失败，提示「导入失败：JSON 格式不合法」，列表无变化
3. 上传一个缺少 `opc` 根字段的 JSON 文件
4. 提示错误，列表无变化，不产生空白 OPC 记录

**导入空 agents / channels 的 OPC**
1. 导入一个仅含 OPC 基本信息、`agents`/`channels`/`bindings` 均为空数组的 JSON
2. 导入成功，OPC 卡片出现，进入 Agent 列表为空，进入绑定列表为空，不崩溃

## 快照与部署联动

> 此工作流验证：部署前手动创建快照 → 完成部署 → 在快照列表中确认快照仍然有效。

1. 选中一个 OPC，在快照区点击「创建快照」，填写标签（如 `deploy-before`），确认
2. 快照列表出现新记录，标签显示「deploy-before」，带紫色标签（手动快照）
3. 前往 `#/deploy`，选择该 OPC 和一个已配置 Daemon 的 Office，点击「立即部署」
4. 等待部署完成（状态变为绿色 ✓），返回 `#/opc` 选中该 OPC
5. 快照列表中「deploy-before」快照仍然存在，未被覆盖或删除
6. 点击该快照的「恢复」，确认后进入 Agent 列表，数据与部署前一致

---

## 下线 OPC

> 「下线」操作仅对运行中的 OPC 可见

1. 选中运行中的 OPC，点击「下线」
2. 出现确认对话框，列出影响内容：代理停止运行、频道断开、Office 解关联
3. 取消后 OPC 保持运行中状态；确认后状态变为「已停止」
4. 列表中该 OPC 从「运行中」分组移到「已停止」分组

---

## 边界情况

- 列表为空时右侧面板显示「请创建团队」提示，无可操作按钮
- OPC 卡片中绿色脉冲点仅在运行中时显示
- 相对时间（「X 分钟前」）在超过 60 分钟后显示「X 小时前」，超过 24 小时显示「X 天前」
- 统计数据加载失败时数值显示为 `0`，不崩溃
